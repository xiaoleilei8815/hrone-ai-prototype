产品结论#

本页面面向具备用工分析权限的管理者，提供从需求、发单、派遣、到场、试工、出勤到留存的完整履约分析。用户在一个页面内完成日期与组织筛选、整体指标判断、流失定位、分维度对比和明细核验。系统自动聚合人数和比例，不提供人工修改业务数据的能力。

前端必须保证筛选、图表、表格与导出使用同一查询上下文；后端必须保证所有汇总比例由汇总人数相除，不允许先计算单行比例再取平均；测试必须同时验证人数、分母、汇总、边界值和权限。

业务背景与目标#

业务问题#

  • 管理者需要同时判断整体需求是否满足、人员在哪个履约环节流失，以及不同组织、供应商和工种之间的履约差异。
  • 原始业务数据跨需求、发单、派遣、到场、试工、出勤与在职记录，若各模块分别统计，容易出现时间范围、去重和分母不一致。
  • 报表需要明确展示计算口径，并允许授权人员维护租户级统计规则和需求满足率豁免规则。

页面复用现有权限系统。权限由租户管理员在现有权限配置功能中分配，本项目不新增权限管理页面。后端必须在接口层校验权限，前端隐藏无权限入口；仅隐藏按钮不能作为安全控制。

数据权限#

  • 用户只能查询现有组织数据权限覆盖的区域、物理仓和组。组织选择器不展示无权限节点。
  • 供应商与工种数据由用户可见组织范围内的数据聚合得到，切换维度不得扩大数据范围。
  • 租户级规则对所有报表查看者生效，但只有取得相应按钮权限的用户可修改。
  • 规则保存记录租户、操作者、时间、修改前值和修改后值。

页面布局#

  1. Portal 顶部菜单和页面标签沿用现有框架，页面标题为“用工分析报表”。
  2. 标题右侧依次展示“导出图片”“统计规则配置”“需求满足率豁免规则”，按钮由按钮权限控制。
  3. 业务内容依次为筛选区、指标总览、履约漏斗、对比分析图、对比数据明细和指标口径。
  4. 页面使用一个主垂直滚动容器；窄屏时指标卡横向滚动，宽表格在自身容器内横向滚动。

筛选交互规则#

  • 按天时开始日期等于结束日期；按周为自然周周一至周日；按月为自然月；直接修改日期后快捷项自动切为自定义。

  • 查询期间按钮进入加载状态并禁止重复提交。成功后所有模块使用同一 queryId 或数据版本。

环比规则#

  • 仅按周和按月展示环比。自定义与按天不展示。
  • 当前周期若受数据截止日影响，上一周期取相同已过天数。例如本月统计到 14 日，上月只统计 1 至 14 日。
  • 上涨使用绿色，下降使用红色，持平使用中性色。上一周期为 0 或无数据时显示—。
  • 比率型变化使用“%”，不使用“个百分点”；数值型同时展示百分比变化和人数差值。

通用规则#

  • 两类配置均按租户全局生效。保存后，新查询立即使用新规则；已打开页面在下一次查询时获取最新配置。

需求满足率豁免规则#

  • 每条规则包含区域多选、工种多选和豁免天数，天数为 1 至 365 的整数。
  • 任意区域＋工种组合只能命中一条规则。重复时禁止保存并指出冲突组合。
  • 当查询日期范围超过豁免天数时，该组合的仓库需求人数取豁免天数窗口内的最大需求人数；未命中时按完整范围汇总。
  • 支持新增和删除。每条规则至少选择一个区域和一个工种。

数据口径与公式#

时间与去重#

  • 需求日期范围用于锁定需求批次，之后追踪这些批次的全部履约结果，首尾日期均包含。
  • 人员按需求批次 ID＋工号去重。缺少工号的数据进入数据质量清单，不得静默重复计数。
  • 试工通过人数仅统计结果明确为“通过”的人员；其余到场人员归入试工未通过流失项。
  • 发单按批次与供应商的最新有效分配版本统计；撤回、作废和被替代版本不重复计数。

留存口径#

  • 固定周期为 7 日、30 日、3 个自然月、6 个自然月；自定义周期为 1 至 3650 天。
  • 观察起点为试工通过日。自然月遇目标月份无对应日时取月末。
  • 期间离职或离职后重新入职者不算连续留存。
  • 未满周期和缺少试工通过日期者不进入分母。生产环境单列缺失日期人数。

底层数据表设计与计算示例#

数据分层和表关系#

报表建议采用“业务明细层、日汇总事实层、维度层、规则配置层”四层结构。业务明细层保留可追溯的需求、发单、派遣、到场、试工、出勤和在职事件；日汇总事实层承载报表查询；维度层提供组织、工种、供应商和人员的统一编码；规则配置层保存租户级统计口径和豁免日期。所有事实记录必须携带 tenant_id，任何查询先按租户和用户数据权限过滤，再进行聚合。

dwd_labor_supplier_order_version 需求单＋供应商＋发单版本 tenant_id＋demand_id＋supplier_id＋version_no 保存发单版本，识别最新有效分配

dws_labor_fulfillment_daily 需求单＋组织＋工种＋业务日期 tenant_id＋demand_id＋org_group_id＋job_type_id＋biz_date 报表核心日事实表

核心日事实表字段#

表名建议为 dws_labor_fulfillment_daily。该表每天按需求单、最小组织和工种生成一行。人数均为当日发生量，不保存前端显示比例；所有比例由查询服务按筛选范围汇总分子和分母后计算。

warehouse_id / warehouse_name varchar 是 物理仓编码与名称
org_group_id / org_group_name varchar 是 最小组织组编码与名称

权重生成规则#

  1. 无豁免时，查询日期范围内每一天的 no_exemption_weight 和 exemption_weight 均为 1。
  2. 查询范围命中区域＋工种的豁免配置，并且配置的豁免日期落在需求日期范围内时，仅豁免日期当天 exemption_weight 为 1，其余日期为 0。
  3. 豁免日期不在需求日期范围内时，相当于无豁免，查询范围内所有日期的 exemption_weight 均为 1。
  4. 豁免后的需求人数使用 Σ（daily_demand_count × exemption_weight）；无豁免需求人数使用 Σ（daily_demand_count × no_exemption_weight）。
  5. 权重由数据服务根据租户、区域、工种、需求开始日期和豁免配置生成。前端不得自行计算或修改权重。
  6. 同一需求日期只能命中一条区域＋工种规则。配置冲突时禁止保存，避免多次加权。

数据质量校验#

校验编号 校验规则 处理方式
DQ-01 daily_demand_count、人数事实和权重不得为负 拒绝入仓并告警
DQ-02 no_exemption_weight 必须为 1 拒绝入仓并告警

响应约束#

  • queryId 唯一标识本次聚合。summary、funnel、comparison 和 detail 来自同一 queryId。
  • dataAsOf 由服务端返回，前端不得写死；configVersion 表示本次计算使用的配置版本。
  • 人数为整数。比例返回 numerator、denominator 和 rate，前端显示时四舍五入至 1 位小数。
  • 返回对象 ID 和名称。交互与下钻使用 ID，不以名称作为唯一键。
  • 聚合接口必须返回分子与分母，禁止只返回最终百分比。

非功能要求#

性能与兼容性#

  • 常规查询 95 分位 3 秒内完成；首屏骨架 300 毫秒内出现。
  • 支持现行 PC 浏览器基线，至少验证 Chrome 最新两个稳定版本及 1280、1440 像素宽度。
  • 明细建议最多返回 500 行；超过上限返回 total 与 truncated，前端提示缩小范围。
  • 所有按钮、图例和可下钻图形支持键盘聚焦与 Enter 或 Space 触发。

安全与审计#

  • 所有查询强制叠加租户和用户数据权限，客户端组织 ID 不得绕过权限。
  • 配置保存记录操作者、时间、来源 IP、前后值、版本和结果。
  • 导出权限与查看权限分离，导出事件写入审计日志。

发布与数据核验#

  1. 数据研发提供固定验收数据集及逐层汇总结果，产品、后端和测试共同确认核心公式。
  2. 后端先上线聚合与租户配置接口，完成权限、审计、限流和监控。
  3. 前端联调后对 1280 与 1440 像素执行视觉回归，对所有维度执行交互回归。
  4. 灰度期间抽取至少 3 个租户，对比原始业务单据与报表结果，差异必须解释并归档。
  5. 上线后监控查询成功率、95 分位耗时、配置保存失败率和导出失败率。

上线门槛#

  • 核心公式、供应商不使用责任因子、租户全局配置和权限隔离用例全部通过。
  • 同一 queryId 下卡片、漏斗、图表、明细和导出一致。
  • 无 P0 或 P1 缺陷；P2 缺陷有修复计划并经产品确认不影响核心判断。
  • 配置审计、接口监控和回滚方案可用。
