# OTWS × LABOR DISPATCHING 高保真原型

基于 `spec.md`、`system-function-map.md`、`role-function-map.md` 的全球完整功能规划制作。设计规范采用 HRONE 2026-08-04 快照，交付定位为 **PC 中文业务评审原型**。

## 打开入口

- [整体旅程导航](./journey.html)：五条业务旅程、20 个角色步骤、通知待办和外部财务事件演示。
- [OTWS](./internal.html)：企业 HR、组长、文员、仓长、管理者、系统管理员。
- [LABOR DISPATCHING](./supplier.html)：供应商对接人、供应商管理者。
- [设计与验证报告](./design-review.md)。

推荐通过同一个本地服务访问，以保证两系统演示数据共享。在本目录运行：

```sh
python3 -m http.server 8765
```

然后访问 `http://localhost:8765/journey.html`。不需要安装依赖。HTML 文件也可直接打开，但不同浏览器对本地文件的数据共享行为不同，跨系统串联评审请使用本地服务。

## 界面组织

- 顶部负责跨业务域，侧栏负责当前域，页面标签复用已打开内容。
- 常用状态和周／双周／月平铺；关键字、仓库、查询、重置、更多条件保持一行，1280px 宽度实测筛选区为 56px 高。
- 列表使用紧凑双行身份信息、原币金额和状态；每行最多两个图标操作，操作列保持可达。
- 工时和账单详情采用独立核对抽屉，同屏包含依据、状态、操作与记录；不为简单查看另建多层页面。
- 排班采用周网格；工作台展示待办及协同结果；分析与全局配置各自独立。

## 可实际演示的操作

1. 组长提出需求 → HR 分发 → 供应商安排人数与班次 → 企业确认安排。
2. 文员／组长修正异常、填写依据 → 内部确认 → 供应商确认工时或提出异议。
3. 供应商工时确认后生成对应样例账单 → HR 确认 → 供应商复核。
4. 提交演示发票，校验必填、币种、金额、重复编号 → 自动生成模拟报账编号并进入审批中。
5. 旅程页“外部事件演示台”模拟财务部分或全额付款 → 两端查看财务状态。业务系统本身没有手工标记付款入口。
6. 筛选、状态切换、分页、详情、批量确认、排班调整、记录新增、部分配置资料编辑、账户启停、字段选择导出。
7. 待办处理后归档为已办；统一消息中心入口分别展示待办数与未读通知数；角色切换及无权限深链接处理。

两系统使用当前浏览器本地演示数据，刷新保留操作。底部“重置演示数据”会恢复初始样例；仅影响这套原型，不修改三份需求文档或任何真实业务系统。

## 演示方式

建议从旅程页第三条“从 T+1 考勤到双确认工时”开始：

- 文员确认任意待内部确认记录。
- 切换供应商对接人复核该人员工时。
- 切换 HR，在周期账单查找 `BL-AUTO-` 开头的自动生成账单并确认。
- 切换供应商管理者复核同一账单，填写新的发票编号，勾选“使用演示发票”，提交报账。
- 在外部事件演示台模拟财务回执，再从供应商付款列表查看。回执演示优先选择最近加入的审批中／部分付款账单，并明确显示更新的编号，不保证选择刚提交的那一笔。

预置样例分布在不同业务阶段，方便独立评审，不要求从第一步全部创建。已做过的演示记录可以继续查看，需重新从初始阶段演示时使用重置入口。

## 功能覆盖与原型深度

| 功能范围 | 原型深度 |
| --- | --- |
| 企业端 16 个功能模块 | 已映射到 27 类业务页面中的相应工作区；模块与页面不是一一对应 |
| 供应商端 11 个功能模块 | 在相同业务对象下提供本供应商视角、操作及角色入口 |
| 考勤—工时—账单—发票—报账 | 可执行状态流转、异常校验和跨系统同步 |
| 需求与排班 | 支持人数分发及班次调整；不具备生产级排班求解、全量逐人批量派遣和劳动规则计算 |
| 全球规则、币种、协议、预算 | 有列表、详情及相应资料表单；保存作为待审核资料。未实现全部地区审批、规则发布和计算执行机制 |
| 周、双周、月与九币种 | 页面和样例展示、周期筛选、币种一致性校验；自动工时出账采用演示仓库费率与双周期间，非完整生产计费引擎 |
| 发票 | 本次可操作路径采用单账单整单开票；Spec 中跨账单分配、分批报账、贷项冲减仍需专项交互深化 |
| 人员生命周期 | 可查看和办理代表性样例；新建员工与所有历史入场、权限和派遣记录不构成完整生产级关联 |
| 经营分析 | 静态示例统计，与用于状态操作的少量演示记录明确区分 |
| 多语言 | 提供中英切换入口及核心界面词条；详细说明和部分样例仍保留中文，非完整英文／全球语言验收版本 |
| 真实外部能力 | 未连接真实认证、二维码认证、邮件、打卡、财务、银行或文件存储；不构成真实性或生产安全验证 |

## 文件

`journey.html` 为独立导航，`internal.html` / `supplier.html` 为两系统入口，`app.js` 为演示交互，`styles.css` 为统一界面样式，`index.html` 为目录默认入口。

此交付可评审页面拆分、信息密度、核心交互及角色交接。完整功能规划不等于所有功能都已达到工程实现深度；地区规则、完整英文、细分账票分配等仍需在前端设计确认后继续深化。

## 系统标识与消息中心（2026-09-14 已确认）

- 内部系统统一命名 **OTWS**，采用紫色任务核对标识；外部系统统一命名 **LABOR DISPATCHING**，采用蓝色双向派遣标识。登录页、顶部品牌、侧栏、浏览器标题、旅程入口和文档保持一致。
- 顶部只有一个 **消息中心** 入口，同时显示“待办 N”和“通知 M”。N 为当前身份未办理事项数，M 为当前身份未读通知数；待办计数视觉优先，不能合并为一个总数。
- 消息中心一级页签为 **待办／通知**。待办下分 **待办／已办**；通知下提供 **全部／未读／已读** 筛选，每条通知明确标记已读或未读。
- 查看待办、阅读通知或标记已读都不完成业务任务。只有完成规定业务动作才进入已办，保留处理人、时间、动作和结果。
- 通知支持标为已读、标为未读、全部标为已读；仅更新当前身份阅读状态及入口通知数量，不改变待办数量或交易状态。两个系统和不同角色的阅读状态分别保存。
- 消息范围服从当前业务授权；侧栏、全部菜单、工作台入口及旧通知链接统一指向同一个消息中心，不再打开独立通知抽屉。
